# Godot MCP Tools Cheatsheet & Cost Matrix

Матрица стоимости и сценариев использования 21 инструмента `godot-mcp` в соответствии с политикой экономии квот `token-economy`.

---

## 1. Категории инструментов по расходу квоты

| Категория | Инструменты | Политика использования |
| :--- | :--- | :--- |
| **Зеленая (Дешевые / Текстовые)** | `godot_runtime_state` (digest), `godot_editor_read`, `godot_docs`, `godot_project` (check_stale), `godot_node_read`, `godot_profiler` | **Безопасны к регулярному вызову**. Возвращают компактный JSON/текст (~100-300 токенов). |
| **Желтая (Исполняющие / Батчинг)** | `godot_exec`, `godot_game_time` (freeze, step, step_until), `godot_input`, `godot_editor_edit` (run, stop) | **Использовать строго пакетно**. Один вызов скрипта или таймлайн ввода вместо десятков интерактивных шагов. |
| **Оранжевая (Структурные редакторы)** | `godot_node_edit`, `godot_scene`, `godot_animation_edit`, `godot_tilemap_edit`, `godot_gridmap_edit` | **Запрещены для массовых правок**. Если правок > 2, использовать шаблон `EditorScript` в `scratch/` через `godot_exec`. |
| **Красная (Тяжелые / Графика)** | `godot_editor_read` (screenshot_game, screenshot_editor) | **Строго запрещены без прямого указания пользователя**. Скриншоты сохраняются в контексте навсегда. |

---

## 2. Ключевые паттерны и скрытые ловушки (Pitfalls)

### 1. `godot_exec` (Сценарная инъекция в живой процесс)
* **Область видимости**: автозагрузки по имени (например, `GameManager`, `G`), `tree` (SceneTree), `root` (Window), и `holder` (узел, переживающий смену сцен).
* **Возврат данных**:
  * Примитивы (`int`, `float`, `String`, `bool`) возвращаются в чистом виде.
  * Массивы/Словари по умолчанию усекаются до 200 символов! **Всегда возвращайте `return JSON.stringify(...)`**.
* **Асинхронность**: `godot_exec` выполняется синхронно. `await` не поддерживается. Для ожидания используйте связку с `godot_game_time step_until`.

### 2. `godot_game_time` (Детерминированный плейтест)
* `freeze`: останавливает игровое время, но оставляет доступными все инструменты наблюдения (`godot_runtime_state`).
* `step_until`:
  * Продвигает время до истинности GDScript-предиката в `until`.
  * **Критично**: аргумент `report` позволяет вычислить список выражений (например, `["tree.get_nodes_in_group('pieces').size()"]`) в момент остановки **без отдельного повторного вызова инструмента**.

### 3. `godot_runtime_state` (Замена скриншотов)
* `action: "digest"`: собирает трансформы, скорости, анимации.
* Для автозагрузок (`Autoload`): дерево обходит только текущую сцену. Чтобы прочитать синглтон, передайте его в `paths: ["/root/GameManager"]`.
* Добавление метода `func _mcp_state() -> Dictionary` в ключевые контроллеры дает идеальный срез данных для агента без лишнего мусора.

### 4. Жизненный цикл редактора
* **Код скриптов `.gd`**: перезапуск редактора НЕ нужен. `godot_editor_edit stop` $\rightarrow$ `run`.
* **Настройки `project.godot`**: редактор НЕ перечитывает файл с диска. Сначала `godot_project check_stale`, затем перезапуск при необходимости.
* **Артефакты 3D/шейдеров**: перед ручной правкой света или материалов вызывать `godot_validate_meshes` (процедурные меши часто страдают от битых тангенсов/нормалей).
