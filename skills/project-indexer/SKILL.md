# Project Indexer & Architecture Map Protocol

Протокол мгновенной генерации и актуализации компактного архитектурного манифеста `PROJECT_INDEX.md` без сжигания токенов контекста.

## 1. Когда активировать
- Запросы: «создай карту проекта», «карта проекта», «проиндексируй проект», «сделай PROJECT_INDEX.md», «обнови индекс».
- Необходимость составить архитектурный снимок незнакомого проекта без чтения каждого файла вручную.

## 2. Протокол за 1 шаг (Zero-LLM Token Scanner)
1. **Запрещено** читать тела файлов через `view_file` или рекурсивно обходить проект через бесконечные `list_dir` — это сжигает квоты.
2. Создать во временной папке артефактов `scratch/fast_indexer.py` (или `.ps1`) и выполнить его через `run_command`.
   Скрипт обходит директории, исключая служебные папки (`.git`, `node_modules`, `dist`, `__pycache__`, `.godot`, `build`, `data`), парсит AST (классы, функции, роуты, хранилища) и возвращает краткий список сущностей.
3. На основе вывода скрипта создать в корне проекта файл `PROJECT_INDEX.md` (строго $\le 150-200$ строк).
4. В том же шаге создать или обновить `AGENTS.md` в корне проекта с правилом обязательного обращения к `PROJECT_INDEX.md`, чтобы проектная память сохранялась между сессиями.

## 3. Правило навигации для последующих сессий
- Перед любым глубоким поиском по проекту агент обязан сначала прочитать `PROJECT_INDEX.md`.
- При добавлении новых модулей или сущностей — обновлять соответствующие строки манифеста.
